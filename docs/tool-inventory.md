## Migration Status

The original "Wave-1 / Wave-2 / Wave-3" terminology came from the brownfield migration plan (Stories 1.4, 2.6, 2.7, 2.8): tools were rolled onto the per-tool contract in three sequenced batches. As of Story 2.8, all on-disk tools are Wave-1 — every entry is `ready: true` and meets the 8/10 quality bar. The waves no longer describe a partition of the inventory; they describe **the migration cohort a tool landed in**.

Today the inventory uses three orthogonal status flags instead of a single wave number:

- **`ready`** — `true` if the tool meets the contract (AD-2); drives visibility in the home grid, palette, pack pages, search, and embed catalog.
- **`score`** — the 0–10 quality score against `docs/quality-rubric.md`; `ready: true` requires `score >= 8`.
- **`migration-wave`** — the historical cohort (`1` for the initial three flagship tools promoted in Story 2.6, `2` for the 15 tools promoted in Story 2.7, `3` for the 17 tools promoted in Story 2.8). Useful for tracking which stories touched which tool; not a quality signal.

The remaining per-tool contract fields (`urlState`, `history-keys`, `view-source`, `embed-snippet`, `shortcuts`, `pack`) are required for every `ready: true` entry. The audit doc (`docs/quality-audit.md`) and `/quality` page reflect any gap remediation in flight.
