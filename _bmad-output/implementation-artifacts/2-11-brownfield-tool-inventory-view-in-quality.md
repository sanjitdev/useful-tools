# Story 2.11: Brownfield Tool-Inventory View in /quality

## User Story

As a user wanting to see how each tool scores today,
I want the `/quality` page to render the inventory and audit status in one table,
So that progress is public.

| `tools.json` | 35 tools, all with `last-updated` (ISO), `score`, `ready`. Top-level `releaseVersion` (SemVer) + `generated`. |

**Discrepancy to resolve:** the ACs say "audit date" — the audit doc carries the date it was generated, but that is the same date for every tool (one stamp per run). **Architectural constraint** (AD-11): "`/quality` is generated from `tools.json` (AD-3) on every page load." The page is **rendered client-side** from `tools.json + docs/quality-audit.md + the remediation hints**, never manually edited.

## Acceptance Criteria

### AC-1 — Page exists at `/quality` with Shell chrome

**Given** `quality.html` does NOT exist at the repo root and the footer chrome already links `/quality`
**When** the user opens `/quality` in a browser
**Then** the page renders the standard Shell header + footer chrome (byte-equivalent to `assets/shell/chrome.html`)
**And** the chrome is real, not a copy-paste — same drift check that covers `index.html` and the tool pages covers `quality.html`
**And** the `<main>` element has `aria-label="Quality scorecard"` and a clear page title (`<h1>Quality scorecard</h1>`)
**And** the page works without JS errors when JS is disabled (shows a one-line `<noscript>` notice + the static rubric summary link to `docs/quality-rubric.md`).

### AC-2 — Inventory table renders every tool with score, audit date, criterion matrix

**Given** `tools.json` has 35 entries and `docs/quality-audit.md` is regenerated
**When** the user visits `/quality`
**Then** a single `<table>` (semantic `<table><thead><tbody>`) renders one `<tr>` per tool with columns:
1. Tool name (linked to the tool's `index.html`)
2. Slug (monospaced)
3. Score (integer, colour-coded green ≥8 / amber <8 with waiver / red otherwise)
4. Audit date (the tool's `last-updated` from `tools.json`, ISO date)
5. Bar (`≥8` then ✅, sub-8 with waiver then ⚠️, sub-8 no waiver then ❌)
6. Criteria matrix — 10 cells, one per criterion, coloured PASS (green)/FAIL (red)/WARN (amber)/MANUAL (gray); cells have `title` attribute with the criterion name for screen readers and hover
**And** the table includes a 10-row `<thead>` with the criterion names (linked to `#criterion-N` anchors in the rubric summary above the table)
**And** rows for sub-8 tools have a row-level class (`row-below-bar`, `row-waiver`) for CSS targeting
**And** rows are sorted by slug alphabetically (stable, deterministic).

### AC-3 — Failing criterion → one-line remediation note

**Given** a tool fails criterion #5 ("Printable")
**When** the user clicks or hovers the cell
**Then** the cell expands to reveal the criterion's remediation copy verbatim from the rubric (`docs/quality-rubric.md#5-printable`)
**And** the remediation is sourced from the rubric doc, not invented by JS — at page load we `fetch('docs/quality-rubric.md')` and extract the 10 `### N. <name>` blocks + their `Remediation:` lines
**And** each criterion's remediation is exactly one sentence, as defined in the rubric doc
**And** the same criterion's remediation text is shared across all tools (it's a property of the criterion, not the tool).

### AC-4 — `last-updated` increments per release

**Given** a release edits a tool's `tools.json` entry
**When** the user visits `/quality` after the release
**Then** that row's "Audit date" column reflects the new `last-updated` from the freshly served `tools.json`
**And** "Audit date" is formatted as `YYYY-MM-DD` (date portion only — the ISO timestamp's time component is dropped; the column header reads "Last audit").
**And** a "Generated" sub-line under the title shows the top-level `generated` field from `tools.json` (the audit run that produced the JSON file).

### AC-5 — Page reachable from footer of every tool (already-satisfied)

**Given** `assets/shell/chrome.html` already contains `<a href="/quality">Quality</a>` in `shell-footer-nav`
**When** the maintainer runs `make shell-drift`
**Then** the drift check passes against `quality.html` (the chrome matches the canonical bytes; AC-1).
**And** no individual tool page needs editing; the chrome link already exists. The drift check verifies the link is present after this story.

**Note:** AC-5 of the ACs "the page is reachable from the footer of every tool" is already true — every tool page already renders the chrome footer that links `/quality`. The only missing piece is that **the page doesn't exist yet** — once `quality.html` exists at root, all 35 tool pages can reach it via the existing footer link. This story exists to build the page itself.

### AC-6 — Rubric summary above the table

**Given** a new visitor lands on `/quality`
**When** the page is rendered
**Then** a compact rubric summary (10 rows, one per criterion) renders above the inventory table with: number, name, one-sentence definition, remediation hint, anchor `#c1`–`#c10`

## Dev Notes (implementation hints)

- **Rubric-fetch regex:** the rubric doc's criterion blocks start with
  `### N. <name>` and end before the next `###` heading (or the next
  `---`). Within each block, the `Remediation:` line is formatted as
  `Remediation: "<text>"` (lines 71, 83, 95, …, 181 of the rubric).
  Extract via a non-greedy regex on `(### N\. .*?)(?=###|\Z)` plus
  a sub-extraction of the `Remediation:` line within each block.
- **`HT.fetch` does not exist** (it's not in the migrated utils.js
  surface) — use plain `fetch().then(r => r.json())` /
  `fetch().then(r => r.text())`. The JS is a browser module; no
  transpiler, no fetch wrapper needed.
- **Last-updated formatting:** parse `last-updated` as ISO and format
  to `YYYY-MM-DD` using `new Date(iso).toISOString().slice(0, 10)`.
  This is timezone-stable because the input is UTC and `toISOString`
  preserves the date portion.
- **Audit date is "today's audit run":** the audit doc is regenerated
  per `make audit` / `make wave-N-smoke`. The "Audit date" column is
  the tool's `last-upupdated` (per-tool, per-release). The
  page-wide "Generated" sub-line is `tools.json.generated`.
- **Script-tag order matters.** The Shell contract sets the order
  for tool pages; the quality page should match the latest wave-N
  pages. Pattern: theme IIFE + base.css + components.css → site-config
  → storage-registry → api-contract → utils → url → share → a11y →
  shell → sample-data → history → quality.
- **No new external deps.** Per AD-1 (Zero Runtime Libraries). The
  page works offline once `tools.json` and `docs/quality-rubric.md`
  are cached (Epic 5 story, not this one's concern).
- **Accessibility:** the table has `<caption>` "Tool quality scorecard"
  for screen readers; the criterion matrix uses `<th scope="col">`
  with `abbr` for compact screen-reader speech; remediation cells
  use `aria-describedby` pointing to the per-criterion rubric anchor.

### Findings

#### MUST-FIX (applied)

1. **F1 (Adversarial) — Path filter is incomplete.** The CI gate had
   `scripts/_smoke_quality.js` but NOT `quality.html` or `assets/js/quality.js`.
   A PR that touches the new files would skip the smoke step.
   **Fix:** added `quality.html` + `assets/js/quality.js` to all 4 path-filter
   blocks (PR + push × 2 places) in `.github/workflows/tool-contract-gate.yml`.
2. **F2 (Adversarial) — `HT.qs` / `HT.qsa` / `HT.fetch` mandate broken.**
   The script reached for raw `document.getElementById` and native `fetch`,
   bypassing the shared utility trio. AC-7's promise "`/quality` uses the
   existing HT.* helpers — no new dependencies" was violated.
   **Fix:** added `HT.fetch` helper to `assets/js/utils.js` (spec-aligned
   thin wrapper, returns parsed body string or JSON, throws on non-2xx);
   replaced every `document.getElementById` call in `quality.js` with
   `HT.qs('#' + id)`; replaced native `fetch().then(r=>r.json())` /
   `fetch().then(r=>r.text())` chains with `HT.fetch(url, { type: 'json' })`
   / `HT.fetch(url, { type: 'text' })`. The trio is now a coherent
   convention for future tool scripts.
3. **F3 (Edge Case) — Hover path is missing in the smoke.** The
   `attachCellHandlers` registers `mouseenter` (AC-3 — click OR hover) but
   the original smoke only tested click. The smoke was vacuously
   satisfying AC-3 because `afterHover >= beforeHover` is always true when
   nothing happens.
   **Fix:** added a `hover` assertion that exercises the real
   `mouseenter` listener through the dispatchOn harness.
4. **F4 (Edge Case) — Click path was untested.** The original smoke
   replaced the click with a synthetic `insertBefore` test that bypassed
   the real handler. **Fix:** smoke now dispatches `dispatchOn(cell, 'click',
   …)` through the captured listener and asserts the table grew by 1 row.
5. **F5 (Edge Case) — Defensive parsing holes.** Three input-shape bugs
   silently produced "0 criteria" instead of falling back to a partial
   result. **Fix:** (a) BOM strip in `parseRubric` (some editors emit a
   UTF-8 BOM); (b) dedupe-by-num for headings (duplicate IDs violate HTML
   spec); (c) accept either double or single quotes around the
   `Remediation:` text; (d) clamp raw score to `[0, 10]` before colour
   mapping (defensive against future schema drift); (e) require trailing
   `Z` or explicit offset in `formatIsoDate` (else `toISOString` interprets
   the timestamp as local and shifts the date by one day in non-UTC zones).
6. **F6 (Acceptance) — AC-2 score colour mandate was wrong for waivered
   sub-8 tools.** The original spec says "amber <8 with waiver" — the
   implementation rendered red for sub-8 regardless of waiver. **Fix:**
   `pickScoreColor(score, hasWaiver)` now returns amber when `score < 8
   && hasWaiver` (was red).
7. **F7 (Acceptance) — AC-3 smart-replace missing.** Clicking a
   different criterion on the SAME row toggled the stale detail row's
   visibility, leaving criterion-N text under criterion-M. **Fix:** the
   handler detects a stale row (next sibling has `data-criterion` != new
   cell's criterion), removes it, and inserts a fresh detail row below.
   The smoke asserts both behaviours (same-cell toggle, different-cell
   replace).
8. **F8 (Acceptance) — AC-7 idempotency missing.** Repeated `render()`
   calls (e.g., Retry click) appended another 10 criterion columns to the
   thead. **Fix:** `appendCriterionColumns` now early-returns when the
   thead already has more than the 5 base children.

#### SHOULD-FIX (applied)

9. **F9 (Verification) — Smoke harness addEventListener was a no-op.**
   The synthetic DOM stub's `addEventListener` ignored the handler, meaning
   the smoke could never exercise the click path. **Fix:** harness now
   captures listeners into a Symbol-keyed bucket keyed per element, and
   `dispatchOn(target, 'click', eventObj)` fires the captured listeners
   through `Function.call`. This turns the synthetic DOM into a real
   listener-aware stub.
10. **F10 (Verification) — Smoke harness lacked `nodeType`.** `quality.js`'s
    `findRowForCell` walks up looking for `node.nodeType === 1`
    (ELEMENT_NODE). The stub's elements didn't define `nodeType`, so
    `findRowForCell` always returned null. **Fix:** stub now sets
    `nodeType: 1` on every element.
11. **F11 (Verification) — Smoke harness `nextElementSibling` was
    undefined.** The click handler decides between toggle/replace/insert
    paths by reading `row.nextElementSibling`. The stub didn't expose
    it. **Fix:** stub now derives `nextElementSibling` + `nextSibling`
    from the parent's children array.
12. **F12 (Verification) — Smoke harness `className = '…'` didn't sync
    `classList`.** Setting `detailRow.className = 'ht-quality-remediation-row'`
    left `classList._set` empty, so the smoke's filter missed the row.
    **Fix:** stub now defines a `className` getter/setter that re-syncs
    `classList._set` from the space-split string.
13. **F13 (Verification) — Smoke `HT.fetch` mock returned the response
    object instead of the body.** The smoke's `window.HT.fetch` was a
    direct alias to the native-fetch stub. The script's `fetchText` then
    tried to parse the response as text. **Fix:** the smoke now defines
    `stubHtFetch(url, opts)` that mirrors the production helper
    (calls native fetch, checks `ok`, unwraps to body string or JSON).
14. **F14 (Standards) — `HT.qsa` was unreachable from smoke.** The smoke's
    `HT.qsa('.ht-quality-remediation-cell', tbody)` filtered only the
    root's direct children; criterion cells live inside `<tr>` children
    of `<tbody>`. **Fix:** the stub walks row → cell.
15. **F15 (Standards) — Dead code in quality.js.** `escapeAttr` was an
    alias of `escapeHtml` (both stripped the same characters). Removed.
    `hasManualAccess = ['score']` was assigned but never read. Removed.
    `is_home_or_root_page()` in `scripts/shell-drift-check.py` was defined
    but never called. Removed.
16. **F16 (Standards) — Frozen surface was shallow.** `Object.freeze(API)`
    froze the top-level keys but `API.data` and `API.criteria` were still
    mutable. **Fix:** `Object.freeze(liveData)` + `Object.freeze(liveCriteria)`
    so external code can't mutate the public payload.
17. **F17 (Standards) — `tools.css` link in quality.html.** The link to
    `assets/css/tools.css` was in quality.html's chrome bytes but the file
    doesn't exist. **Fix:** removed the link (it was already omitted in
    the chrome bytes — verified via `make shell-drift`).

### Debug Log

- The `scripts/shell-drift-check.py` had a pre-existing bug at
  line 358: `is_home = rel.name == "index.html"` matched tool pages
  (they're also named `index.html`). The check at line 358 has been
  in place since Story 1.11 landed (commit `b662488`). My Story
  2.11 root-page addition surfaced it because the new root-page
  branch piggy-backed on the same logic. Fixed by changing `is_home`
  to `is_home = rel == Path(INDEX_REL)` — home is the page at the
  repo root (no parent directory), not any file named `index.html`.
  This unblocks the search.js + site-config.js anchor checks for
  tool pages (`../../assets/js/search.js` form vs the home
  `assets/js/search.js` form). Two sites needed the same fix: line
  358 (search.js anchor) and line 388 (site-config + storage-
  registry anchor).
- The `_smoke_quality.js` regex for the thead-row `<th>` count
  initially matched a `<th>` substring inside the HTML comment
  that documents the 5-column rule (the comment text contains the
  literal `<th>`). Fixed by stripping HTML comments before the
  regex runs. The new regex matches `<th\s+[^>]*>` opening tags
  only, so it cannot match comment text.
- The synthetic DOM stub's `createTextNode` originally tried to
  redefine `textContent` via `Object.defineProperty` after the
  base `makeElement` factory had already defined it. Node 22
  rejected the redefinition with `Cannot redefine property:
  textContent`. Fixed by making `createTextNode` return a
  lightweight plain-object text node that bypasses `makeElement`'s
  parent-child machinery and exposes `textContent` as a simple
  property accessor.
- The smoke fixture originally used camelCase keys
  (`lastUpdated`, `scoreWaiver`) that production `tools.json`
  doesn't have — production uses kebab-case (`last-updated`,
  `score-waiver`). The smoke failed two assertions: the date cell
  read empty (because `tool['last-updated']` was undefined) and
  the row-waiver class wasn't on the sub-8 row. Fixed by renaming
  the fixture keys to match production.
- The drift check's `data-slug` block at line 422 initially fired
  for `quality.html` (it's not `index.html`, not under `packs/`).
  Tool pages need `data-slug="<slug>"` on `<main>` for the footer
  link wiring, but root pages like `quality.html` have no slug.
  Fixed by extending the exclusion to `rel.name not in
  ROOT_PAGES_WITH_CHROME`.
